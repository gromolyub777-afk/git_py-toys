# git_py-toys

## Git Committer v3 (`git_committer_v3.py`)

GUI-приложение (Tkinter) для двусторонней синхронизации папки и git-репозитория
(КОММИТ / ВЫГРУЗИТЬ ИЗ РЕПО) с авто-режимами, dry-run, бэкапами, тегами и откатом.
Версия 3 — ООП-рефакторинг по ТЗ: модульные функции и «god class» `CommitterApp`
разложены на классы с чёткими зонами ответственности (`Config`, `GitRunner`,
`FileSync`, `BackupManager`, `Notifier`, `RepoService`, `AutoScheduler`,
`TaskRunner`, `LogPanel`, `MainWindow`), всё остаётся в одном `.py`.

### Запуск

```bash
python git_committer_v3.py
```

Зависимости: только стандартная библиотека Python (tkinter) и установленный `git`.
На Linux при отсутствии Tk: `sudo apt install python3-tk` (или `pacman -S tk`).

### Как пользоваться

1. Запустите приложение — файл `config.json` создастся сам, ничего настраивать не нужно.
2. Укажите **только два поля**:
   * **Папка** — откуда коммитить (кнопка «…» рядом открывает выбор папки);
   * **Репозиторий** — **ссылка** на git-репозиторий (не путь к папке!):
     `https://github.com/user/repo.git`, `git@github.com:user/repo.git`,
     `ssh://…`, `git://…`, `file:///…` или путь, оканчивающийся на `.git`.
     Удобно вставлять из буфера обмена кнопкой «…» рядом с полем.
3. Нажмите большую зелёную кнопку **КОММИТ**.
4. Маленькая кнопка **«...»** справа внизу открывает файл `config.json` в системном редакторе.

Оба пути сохраняются в конфиге — при следующем запуске достаточно просто нажать «КОММИТ».

### Что делает кнопка КОММИТ

* если репозиторий задан URL — клонирует/обновляет его в подпапку `repo_<id>`;
* синхронизирует содержимое папки-источника в рабочую копию репозитория;
* выполняет `git add -A` и `git commit` (с автором и сообщением из конфига);
* при `"push": true` — пушит в `origin`;
* пишет историю удачных коммитов обратно в `config.json`.

### Структура config.json (генерируется автоматически)

```json
{
  "source_folder": "/путь/к/папке/откуда/коммитим",
  "repository": "https://github.com/user/repo.git",
  "branch": "main",
  "commit_message": "Автокоммит: {datetime}",
  "author_name": "Git Committer",
  "author_email": "committer@local",
  "push": false,
  "history": []
}
```

Необязательные ключи (`branch`, `commit_message`, `author_*`, `push`) можно править
в конфиге через кнопку «...», но для работы достаточно указать лишь папку и репозиторий.

В v3 config.json полностью владеет класс `Config` (атомарная запись, битый файл
сохраняется как `config.broken.json`). Для старых интеграционных тестов сохранён
тонкий compat-слой модульных функций (`load_config`, `save_config`, `run_git`,
`commit_all`, `download_from_repo`, …) — каждая делегирует соответствующему классу,
дублирования логики нет.
## Конфиг (config.json)

| Ключ | Назначение |
|---|---|
| `source_folder` | папка, откуда берём файлы |
| `repository` | **ссылка** на репозиторий (https/git/ssh/file:// или путь *.git) |
| `branch` | ветка для коммита (создаётся, если её нет) |
| `commit_message` | сообщение; `{datetime}` подставляется автоматически |
| `author_name`, `author_email` | автор коммита |
| `push` | пушить ли после коммита |
| `delete_extra` | удалять в рабочей копии файлы, отсутствующие в источнике |
| `history` | последние 50 коммитов |

Конфиг генерируется при первом запуске, пишется атомарно (`mkstemp` + `os.replace`),
битый файл сохраняется как `config.broken.json` и пересоздаётся.

Служебные папки `.venv`, `node_modules`, `__pycache__`, `.idea`, `.vscode` и т.п.
в репозиторий не копируются.

### `git_committer_v2.py` — реализация ТЗ «Git Committer v2»

Помимо прямого процесса (папка → репо, кнопка **КОММИТ**) добавлен обратный
(репо → папка, кнопка **ВЫГРУЗИТЬ ИЗ РЕПО**) и авто-режимы по таймеру.

**UI:** поля «Папка», «Ссылка репо» («…» — вставить из буфера), «Папка выгрузки»;
чекбоксы «☐ Авто-коммит (5 мин)» и «☐ Авто-клон (5 мин)» с индикаторами
«следующий через MM:SS» и кнопками «Сейчас»; строка статуса, лог; внизу кнопка
«…» — открыть `config.json`.

**Конфиг v2** (новые ключи добиваются дефолтами в старых файлах):
`auto_commit=false`, `auto_clone=false`, `auto_interval_min=5`, `download_folder=""`.
Запись атомарная (`mkstemp` + `os.replace`, временный fd закрывается при ошибке);
битый файл → `config.broken.json` + пересоздание.

**Прямой процесс:** проверка ссылки → клон в `./repo_<имя>_<sha1[0:8]>`/fetch →
безопасный checkout ветки (создание без `-B`, без сброса истории) →
`pull --ff-only` только при чистом дереве → копирование источника (ignore-список) →
`add -A` / `commit --author` → `push -u origin <branch>` при `push:true` → история.

**Обратный процесс:** clone/fetch/checkout/pull → выгрузка рабочей копии (без `.git`)
в `download_folder` (или `source_folder`) → удаление лишних файлов с подтверждением
(GUI) или безусловно (авто-режим) → лог: файлов, ветка, sha → запись в историю.

**Авто-режимы:** один `root.after(1000, tick)`; включение чекбокса только планирует
(`next_run_at = now + interval`), «Сейчас» — немедленный запуск в фоне; занято —
пропуск и сдвиг; оба включены → приоритет авто-клону; без `messagebox` — только лог
и статус; пропуск при пустом `repository` или отсутствии папки; флаги сохраняются
при любом изменении.

Все git-операции — в фоновом потоке (`TaskRunner` + `queue.Queue`);
`GitRunner.run` использует `GIT_TERMINAL_PROMPT=0`, `GIT_EDITOR=true` и таймаут.

```bash
xvfb-run -a python tests/test_committer.py      # регрессия: 25 проверок
```
